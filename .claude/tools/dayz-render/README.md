# dayz-render — рендер предметов в PNG (Blender, Cycles)

Готовые картинки кладём в `Рендеры\<Мод>\<classname>.png` — только classname, без приписок (прозрачный фон, кадр обрезан по предмету).

Blender: `G:\SteamLibrary\steamapps\common\Blender\blender.exe` (5.2, в нём есть numpy). Видеокарта RTX 4070 (OptiX), один предмет рендерится примерно за 20 с.

## Бинарные модели (ODOL, любые моды)

```
blender.exe -b --factory-startup --python render_p3d.py -- <model.p3d> <out.png> --root=<папка мода> [--size=2000] [--samples=256] [--elev=22] [--azim=-28] [--flat]
```
Дополнительные опции:
- `--prefix=vb_ab=<папка>` — привязать префикс PBO к папке исходников (`;` между несколькими).
- `--sel=<json>` — hiddenSelections из конфига: `{"selections":[], "textures":[], "materials":[]}`. Выделения накладываются от крупных к мелким. Пример — `example_batch_detectors.py`: читает конфиг мода и сам пишет json.
- `--tex=<paa>` — одна подмена текстуры (ткани EFT).
- `--upside` — перевернуть модель.
- `--elev`/`--azim` — ракурс. Например, EFT_SkullRing снят с `--elev=-35 --azim=152`.

Контактный лист для проверки пачки: `sheet.py -- <папка> <лист.png> [--cols=8 --cell=260]`. Он заодно проверяет альфу в углах.

`--root` — папка, от которой считаются пути текстур в модели. Для EFT это `modding\mod_EscapeFromDayZ`, в ней лежит папка `EFT`. Пути ванили `dz\...` ищутся на `P:\`.
Текстуры конвертируются через ImageToPAA в `texcache\` рядом со скриптом.

- `odol_read.py` — своя читалка ODOL v54 (первый визуальный LOD: вершины, нормали, UV, грани, текстура и rvmat на грань).
  Справочник — декомпилированный BisDll (`ScripyZz/BisDLL-Arma-3`), его код не копировался.
  Отличия DayZ от Arma, найденные 11-15:
  - заголовок (ModelInfo, анимации) не совпадает, поэтому таблица адресов LOD ищется перебором;
  - встроенные материалы версии 20 не совпадают с разметкой Arma (там ≤ 11), поэтому блок пропускается до заголовка граней;
  - `pointToVertex`/`vertexToPoint` пустые.
- `rvmat_read.py` — читает rvmat в обоих видах: бинарном (raP) и текстовом.
- `_nohq` в DirectX-конвенции, для Blender инвертируется G. `_smdi`: G — блик, B — глянец.

## Сгенерированные материалы VB_AnomaliesBosses (MLOD)

`render_mat.py <Ключ> <out.png> --transparent --frame=1.1 --size=2000`. Геометрия берётся из `tools/ab_materials.py` мода.
Текстуры ожидаются как TGA в `tex\` рядом со скриптом: распаковать `.paa` мода через ImageToPAA.

## Одежда и персонажи: веса костей (2026-11-23)

- `odol_read.read_bone_weights(data, lod)` — веса вершин LOD: сразу за нормалями STCoords (по 8 байт), затем на вершину
  `AnimationRTWeight` 12 байт: int число костей + 4 пары (кость подскелета u8, вес u8; сумма = 255). Кость подскелета ->
  кость скелета — `lod["sub2skel"]` (таблица в начале LOD). Проверено на ExoPrivod_m (ODOL v54).
- `odol2mlod.py` для моделей со скелетом пишет выделения костей с весами (MLOD хранит вес в выделении). Круг
  ODOL -> MLOD -> binarize на сервоприводе OOTS: те же LOD, грани и прокси, веса совпали у всех вершин. Скелет
  восстанавливается в model.cfg (у одежды OOTS — `DayzTemporarySkeleton`, 159 костей).
- Защищённые модели без таблицы адресов LOD (шлем IMP): `scan_lod_starts` ищет LOD по сигнатуре «0 прокси, кости
  подскелета, число костей». У LOD с прокси этот 0 — последнее поле последней записи прокси; `_proxy_prefixed_start`
  отступает назад к настоящему началу (2026-11-23, до этого прокси фонаря и ПНВ шлема терялись).

## Свечение (2026-11-26)

- Цвет свечения = цвет текстуры × `emmisive` из rvmat, как в игре. Раньше брался только `emmisive`, и неон с
  `emmisive {1,1,1,22}` (наш `er_neon.rvmat`) выходил белым вместо красного или бирюзового. `--emit=<k>` —
  множитель силы свечения (по умолчанию 1, как было).
- Модели с hiddenSelections (бирюзовый синтез у аккумулятора) — `--sel=<файл json>`, путь к файлу, не строка.
