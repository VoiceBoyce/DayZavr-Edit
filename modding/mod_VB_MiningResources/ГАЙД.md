# VB_MiningResources — гайд

Своя замена купленного BRDK_GoldRush (руда, сервер 18). ТЗ: [ТЗ_VB_MiningResources.md](ТЗ_VB_MiningResources.md).
Механики перенесены 1:1, вместе с особенностями старого мода; проверки лицензии и внешних запросов нет.

## Состав

| Папка | Что |
|---|---|
| `VB_MiningResources/` | клиентский PBO: `config.cpp` (генерируется), `stringtable.csv` (генерируется), старые модели в `m\`, новые в `data\items\`, скрипты `scripts/4_World` |
| `VB_MiningResources_Server/` | серверный PBO (в `@Servermod\Addons`): настройки, результаты добычи и промывки, пресс, плавка |
| `@VB_MiningResources/`, `@VB_MiningResources_Server/` | собранные подписанные моды (`pbo.ps1 build`) |
| `настройки/settings.json` | настройки для сервера 18: `Instance_1\VB_Mods\VB_MiningResources\settings.json` |
| `tools/` | `import_assets.py` (перенос моделей, разово), `gen_config.py` (config.cpp + stringtable), `check_refs.py` (пути в моделях), `make_settings.py` (settings.json из GoldRush.json), `gen_mr_models.py` (новые модели и текстуры → `data\items`), `render_mr_models.py` (проверочные рендеры), `deploy18.py` (выкладка на 18 и в готовые моды) |
| `старый мод/` | BRDK_GoldRush как образец, `_разбор/` — восстановленный код |

Правка предметов — в `tools/gen_config.py`, потом `python -I tools/gen_config.py` и `build`.

## Классы

`<Рес>` = Gold, Silver, Bronze, Iron, Titanium (металлы, плавятся в чаше) и Coal, Rubin, Nephrite, Sulfur (камни, прессуются).

| Что | Новый | Старый (наследник нового) |
|---|---|---|
| песок | `VB_MR_<Рес>_Sand` | `BRDK_<Рес>_Sand` |
| самородок / кусок | `VB_MR_<Рес>` | `BRDK_<Рес>` |
| слиток / брикет | `VB_MR_<Рес>_Bar` | `BRDK_Big<Рес>` |
| жила (объект карты) | `VB_MR_<Рес>_Vein` | `BRDK_<Рес>_Ore` |
| набор пресса / пресс / чаша | `VB_MR_Press_Kit` / `VB_MR_Press` / `VB_MR_MeltingBowl` | `BRDK_Press_kit` / `BRDK_Stone_Press` / `BRDK_MeltingBowl` |
| огранённый камень (редкая находка) | `VB_MR_Rubin_Gem`, `VB_MR_Nephrite_Gem` (база `VB_MR_Gem_Base`) | — |

- Bronze для игрока — **медь** на всех стадиях; имя класса осталось `Bronze`.
- Старые классы: старая модель, в описании «Старый образец». Добыча и промывка выдают только новые,
  переработка старого даёт новое (поиск записи настроек: точное имя, потом `IsKindOf`).
- В крафтах DRL у компонентов с рудой `UseInheritance = 1` — старые засчитываются наравне с новыми.
- Слоты остались `BRDK_STONES` / `BRDK_METALS` (по ним в сохранении лежат вложения прессов и чаш).
- **Чаша в скриптах — `Cauldron`** (без своего класса): костёр пускает на треногу только тип ровно `Cauldron`
  (E83). Логика чаши — в `modded class Cauldron` под признаком `m_VB_MR_IsMeltingBowl`.
- Старые модели: пути внутри `.p3d` переписаны байтами `brdk_goldrush_client` → `vb_miningresources\m` (та же длина),
  поэтому всё лежит в подпапке `m`. Материалы `.rvmat` переведены в текст. У жил, чаши, пресса, набора и старых
  `BRDK_*` модели старые.

## Новые модели (27 ресурсов)

- 5 форм на 27 ресурсов: `vb_mr_sand` (мешочек), `vb_mr_nugget` (самородок), `vb_mr_chunk` (кусок камня),
  `vb_mr_ingot` (слиток с клеймом), `vb_mr_briquette` (брикет). Цвет и материал — через секцию `camo`
  (`hiddenSelectionsTextures`/`Materials` в `config.cpp`), таблица класс → модель/текстура — `data\items\mapping.json`.
- Модели в исходниках — MLOD. **Сборка клиента только с `-Binarize`** (`pbo.ps1 build ... -Binarize`): нужна ссылка
  `P:\VB_MiningResources` → папка исходников `VB_MiningResources` (binarize ищет файлы по префиксу на `P:\`).
- Пересоздать модели и текстуры: `python -I tools/gen_mr_models.py`, затем `gen_config.py`. Проверка вида —
  `render_mr_models.py`, готовые рендеры в `Рендеры\VB_MiningResources\` (`_сводка.png` — все сразу).
- Вид в игре проверен на стенде (2026-11-17, второй прогон): цвета всех форм верные. В одном прогоне стенда все
  предметы, даже ванильные, были белыми — это был сбой того запуска клиента, не мода.

## Настройки (`settings.json`, версия 2)

Поля GoldRush.json (описание — `Instance_1\BRDK_MODS\инструкция для руд\ИНСТРУКЦИЯ.cpp` на 18): `GoldInRiverSearchTime`,
`MinCountInRiver`/`MaxCountInRiver`, `BadRiverBounty`, `MeltUpdatePeriod`, `MeltTempTreshold`, `MineTools`,
`VeineDataDataList`, `SandDataList`, `OreDataList`. Новые с версии 2 (файл версии 1 дополняется сам и перезаписывается):

| Поле | Что |
|---|---|
| `PressUpdatePeriod` | шаг прессовки, с (5) |
| `MineToolsData` | инструменты с настройками: `Tool` (класс, подходят наследники), `MineTimeMul`, `ToolDamageMul`, `OreChanceAdd`, `ExtraRollsMin/Max`, `RareChanceAdd`, `Veins` (какие жилы можно, пусто — все). Новая кирка = новая запись, без пересборки |
| `MineTools` | инструменты без бонусов (старый список) |
| жила: `RareItem`, `RareChance` | редкая находка, один бросок на всю добычу (рубин и нефрит: огранённый камень, 2 %) |
| песок/руда: `Portion` | сколько штук берётся за раз (0 — полный стак: песок 10, самородки и куски 5) |
| `PanZones` | «золотоносные реки»: `Name`, `Position` [x, y, z], `Radius`, `Sands` [{`SandName`, `ChanceMul`}] |
| `AmberItem`, `AmberSourceClass`, `AmberRadius`, `AmberChance` | находка при промывке рядом с объектом (янтарь `VB_AR_Amber` у рощи `VB_AR_Heart`, 60 м, 3 %) |

Игрок получает инструменты, жилы и рецепты от сервера при входе (RPC по полям, E85), поэтому полоса действия,
подсказки и новые кирки совпадают с настройками без пересборки клиента.

Прогресс пресса и чаши хранится в `VB_Mods\VB_MiningResources\progress.json` по постоянному ID станка (запись
раз в минуту и при остановке сервера); формат сохранения мира не меняется.

## Установка вместо BRDK_GoldRush

За один рестарт: убрать `@BRDK_GoldRush` и `BRDK_GoldRush_SERVER.pbo`, поставить `@VB_MiningResources` и
`VB_MiningResources_Server.pbo`, положить settings.json. **Не запускать сервер ни с одним из двух модов** — предметы
`BRDK_*` удалятся из сохранения. Ключ тот же DayZavrN.

## Ревью кода (2026-11-17)

Четыре направления: безопасность, серверная логика, память и нагрузка, клиент и конфиг. Утечек и лишней нагрузки нет,
ваниль мод не ломает. Исправлено (каталог ошибок E87–E92):
- RPC «данные с сервера» принимается только у игрока — раньше клиент мог подменить серверу инструменты и рецепты;
- разборка пресса — `CCTCursor` (было 20 м без проверки стен), набор пресса ставится не дальше 7 м
  (`VB_MR_KIT_MAX_DISTANCE`), набор удаляет сама ваниль;
- двойная добыча одной жилы в один кадр; промывка только у поверхности воды (не у корыта) и после прихода данных сервера;
- ванильная готовка не трогает хранилище чаши (`modded Cooking`) — раньше всё в чаше на огне сгорало за ~1,5 ч;
- удаление чаши целиком (выход игрока, остановка) не стирает прогресс; `progress.json` хранит и станки, которых нет
  в этом запуске (`Missed`, до 30 запусков);
- проверка настроек: null и записи без имени выкидываются, значения вне пределов зажимаются с предупреждением
  в лог, файл `{}` не перезаписывается пустым; кирка при миграции — только если была в `MineTools`; `ExtraRollsMin`
  без `ExtraRollsMax`; порция больше стопки урезается;
- испорченная порода/металл не перерабатываются; металл в чаше у игрока списывается через `DeleteSafe`;
- янтарь только у живой рощи (`VB_IsDead` вызывается по имени, без зависимости от мода Корня);
- данные игроку уходят и при повторном входе к ещё не вышедшему персонажу; подсказка у станка не уходит на сервер;
- результат пресса при полном хранилище падает рядом с прессом, а не в центр модели.

Проверено на стенде после исправлений: компиляция, предупреждения настроек, вызов `VB_IsDead`, готовка (чаша не
портит, котелок портит), добыча, разборка пресса, прогресс чаши после удаления, прогресс пресса после рестарта
(95 → 120 с, брикет), счётчик `Missed`.

## Известное

- одноручный инструмент в `MineToolsData` получит двуручную анимацию добычи (`CMD_ACTIONFB_MINEROCK`) — проверить
  анимацию, если добавят лом или ледоруб;
- шанс промывки делится на число видов песка (И2, баланс — позже);
- подсказка у чаши стоит первой, «Взять» — вторым действием (прокрутка);
- тексты описаний упоминают порции 10/5 — при смене `Portion` в настройках их надо поправить в `gen_config.py`.
